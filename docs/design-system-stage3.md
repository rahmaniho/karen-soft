# Stage 3.1 — Design System و مهاجرت تدریجی صفحات داخلی

تاریخ: ۱۴۰۵/۰۸/۱۳ (2026-11-04)

## محدودهٔ این increment

این مرحله «بازنویسی ظاهر سایت» نیست. توکن‌های موجود در `app/globals.css` حفظ شدند و
فقط قطعات تکراری/ناهمگون به کامپوننت‌های مشترک منتقل شدند. رنگ آبی برند، مسیرها،
محتوای واقعی، قیمت‌های موجود، دموها و هویت جداگانهٔ کارن چاپ تغییر نکردند.

هدف‌های پذیرش:
- کاهش استایل تکراری در کارت‌ها، دکمه‌ها، فرم‌ها، تب‌ها و حالت‌های خطا/خالی.
- حفظ RTL، فوکوس صفحه‌کلید، نام دسترس‌پذیر و ساختار تیترها.
- سبز ماندن regression gateهای موجود.

## کامپوننت‌های مشترک

| قطعه | مسیر | قرارداد |
|---|---|---|
| سطح کارت | `components/ui/card.tsx` | `SurfaceCard` فقط ظاهر سطح را می‌دهد؛ `interactive` بودن صریح است تا کارت اطلاعاتی شبیه لینک رفتار نکند. |
| کارت منبع | `components/shared/resource-card.tsx` | یک لینک نام‌دار و یک tab stop برای کل کارت؛ تصویر تزئینی `alt=""` دارد. برای مقاله/نمونه‌کار/راهنما استفاده می‌شود. |
| دکمه | `components/ui/button.tsx` | `type="button"` پیش‌فرض؛ `loading` دکمه را disabled و `aria-busy` می‌کند ولی نام قابل مشاهده را عوض نمی‌کند. اندازه‌ها حداقل هدف ۴۴px دارند و `min-height` اجازهٔ شکستن متن فارسی را می‌دهد. |
| فیلد فرم | `components/ui/field.tsx` | `FormField` شناسه‌های `hint`/`error` را به کنترل وصل می‌کند؛ `fieldControlClass` سبک مشترک کنترل‌هاست. |
| بازخورد فرم | `components/ui/form-feedback.tsx` | ناحیهٔ live پایدار با تن‌های `idle/loading/success/error/info`؛ خطا `role="alert"` و بقیه `role="status"` دارند. |
| مسیر صفحه | `components/ui/breadcrumbs.tsx` | آخرین آیتم `aria-current="page"` دارد و لینک نیست. JSON-LD جدید تولید نمی‌کند؛ مسیرهای موجود حفظ شدند. |
| حالت صفحه | `components/ui/state-panel.tsx` | `StatePanel` برای 404/خطا و `EmptyState` برای نتیجهٔ خالی. `EmptyState` عمداً `h3` می‌سازد تا داخل صفحهٔ دارای `h1` تعداد تیتر اصلی خراب نشود. |
| تب‌ها | `components/ui/use-tab-list.ts` | منطق مشترک RTL: ArrowRight/ArrowLeft/Home/End، یک tab stop، `aria-controls` و پنل‌های hidden. `singlePanel` برای دموهایی است که فقط iframe انتخاب‌شده را mount می‌کنند. |
| آکاردئون | `components/ui/accordion.tsx` | فوکوس عمودی با ArrowUp/ArrowDown/Home/End؛ اولین پاسخ در SSR باز است و `hidden` واقعاً اعمال می‌شود. |

## مهاجرت انجام‌شده

- `PageHero` اکنون breadcrumb اختیاری می‌گیرد؛ فهرست‌های محصولات/خدمات/نمونه‌کارها/مرکز دانش/راهکارها و صفحه‌های جزئیات محصول/نمونه‌کار/راهکار/مقاله مسیر والد واقعی دارند.
- `InfoGrid`، کارت‌های محصول، کارت‌های منبع در کاتالوگ، راهنماهای خدمات، مقالات مرتبط محصول، کارت‌های راهکار و بخش‌هایی از جزئیات نمونه‌کار/راهکار به `SurfaceCard`/`ResourceCard` منتقل شدند.
- `Catalog` دکمه‌های فیلتر مشترک، جست‌وجوی برچسب‌دار، شمارش نتیجهٔ live و `EmptyState` دارد. پارامتر `q` موجود در URL پس از hydration حفظ می‌شود و پاک‌کردن فیلتر آن را هم پاک می‌کند.
- `ProductScreenshots` و `DemoTabs` از hook مشترک تب استفاده می‌کنند. تصاویر غیرفعال دیگر فقط با opacity پنهان نیستند؛ پنل آن‌ها `hidden` است.
- فرم تماس اصلی، فرم کارن چاپ و خبرنامه از بازخورد مشترک استفاده می‌کنند. فرم کارن چاپ خطاهای Zod را به فیلد مربوطه نگاشت می‌کند و اولین فیلد نامعتبر را فوکوس می‌کند. خبرنامه شناسهٔ یکتا دارد.
- صفحه‌های 404 اصلی/کارن چاپ و error boundary سایت اصلی حالت بازیابی مشترک دارند؛ هویت CMYK کارن چاپ حفظ شد.
- CSS مردهٔ `.ks-form-feedback` و `.ks-error` حذف شد. توکن‌های بازخورد برای روشن/تاریک و پوستهٔ همیشه‌تیره تعریف شدند. `[hidden]` در لایهٔ base بر utilityهای display اولویت دارد.

## تصمیم مهم: loading سراسری اضافه نشد

یک `app/(site)/loading.tsx` آزمایشی ساخته شد، اما در خروجی static دو مشکل واقعی ایجاد کرد:
1. HTML اولیهٔ بعضی صفحه‌ها هم `h1` صفحه و هم `h1` حالت بارگذاری را داشت؛ `seo:audit` آن را گرفت.
2. مسیر ناشناختهٔ محصول به‌جای 404 وضعیت 200 می‌گرفت، چون fallback قبل از notFound stream می‌شد؛ `check-routes` آن را گرفت.

بنابراین loading سراسری حذف شد. حالت بارگذاری در این مرحله فقط برای عملیات واقعاً ناهمگام
(ارسال فرم) استفاده می‌شود. اگر بعداً بخش dynamic اضافه شد، loading باید در همان segment
و با تست وضعیت 404/HTML اولیه معرفی شود، نه برای کل سایت static.
